# git fetch

```python
git fetch upstream main
```

**Что это.** Скачивает объекты и ссылки из удалённого репозитория. **Рабочие файлы и локальные ветки при этом НЕ меняются.**

**Зачем.** Это безопасная операция: вы получаете чужие коммиты «на посмотреть», ничего не сливая. В отличие от `git pull`, который тут же делает merge.

## Сигнатура

```python
git fetch <remote> [<ветка>]
git fetch --all
git fetch --prune            # удалить локальные ссылки на исчезнувшие ветки
git fetch --depth=1          # только последний коммит
```

## Параметры

| Параметр | Тип | По умолчанию | Что делает |
|---|---|---|---|
| ``<remote>`` | — | — | Имя удалённого репозитория: `origin`, `upstream` |
| ``--all`` | — | — | Из всех remote сразу |
| ``--prune`` | — | — | Убрать `origin/<ветка>` для веток, удалённых на сервере |
| ``--tags`` | — | — | Забрать и теги |
| ``--depth=N`` | — | — | Поверхностная загрузка: только N последних коммитов |

## Минимальный пример

```python
# Скачиваем нужную ветку преподавателя; локальные ветки при этом не меняются.
git fetch upstream main

# Результат доступен как ссылка upstream/main
git log --oneline upstream/main -5
```

## Типичные задачи

**Посмотреть чужие изменения, ничего не сливая**

```python
git fetch upstream
git log --oneline HEAD..upstream/main      # что есть у них, чего нет у нас
git diff HEAD upstream/main -- l03_rest_api/
```

**Почистить ссылки на удалённые ветки**

```python
git fetch --prune origin
```

## Частые ошибки

- **Путать `fetch` и `pull`.** `pull` = `fetch` + `merge`: он МЕНЯЕТ вашу текущую ветку. `fetch` безопасен — сначала посмотрите, потом решайте.
- **Ожидать, что после `fetch` появится локальная ветка.** Появится только ссылка `upstream/main`; локальной ветки с таким именем нет.
- **В поверхностном клоне (`--depth`) многое работает не так**: `merge-base`, сравнение веток, push чужих ссылок. В CI это частая причина странных ошибок.
