# git check-ref-format

```python
git check-ref-format --branch "$BRANCH"
```

**Что это.** Проверяет, что строка вообще допустима как имя ветки. Код возврата `0` — годится.

**Зачем.** Имя ветки собрано из пользовательского ввода, и в нём может оказаться что угодно: пробелы, `..`, `~`, двоеточие. Лучше отвергнуть на входе, чем получить непонятную ошибку git тремя шагами позже.

## Сигнатура

```python
git check-ref-format --branch <имя>
git check-ref-format refs/heads/<имя>
```

## Параметры

| Параметр | Тип | По умолчанию | Что делает |
|---|---|---|---|
| ``--branch`` | — | — | Проверять как имя ветки (короткая форма, без `refs/heads/`) |
| ``--allow-onelevel`` | — | — | Разрешить имя без слеша |
| ``--normalize`` | — | — | Убрать лишние слеши и вывести нормализованное имя |

## Минимальный пример

```python
# Завершится с ошибкой (и остановит шаг из-за set -e), если имя кривое.
git check-ref-format --branch "$BRANCH" >/dev/null
```

## Типичные задачи

**Понятное сообщение вместо кода возврата**

```python
if ! git check-ref-format --branch "$BRANCH" >/dev/null 2>&1; then
  echo "Недопустимое имя ветки: $BRANCH" >&2
  exit 1
fi
```

## Частые ошибки

- **Что именно запрещено:** пробелы, `~ ^ : ? * [ \\`, две точки подряд `..`, `@{`, начало или конец с `/`, две косые подряд, окончание на `.` или на `.lock`.
- **Команда молчит при успехе** — она сообщает результат только кодом возврата. Поэтому её и ставят под `set -e`.
- **Проверка имени не заменяет защиту от инъекции.** Она говорит, что строка годится как имя ветки, но в shell её всё равно нужно передавать через переменную в кавычках.
