# run

```python
run: |
  set -euo pipefail
  ...
```

**Что это.** Выполняет команды shell на машине-раннере.

**Зачем.** Всё, для чего нет готового действия. По умолчанию на Linux это `bash`.

## Сигнатура

```python
run: одна команда

run: |
  многострочный
  скрипт

shell: bash | pwsh | python | sh
working-directory: <каталог>
```

## Параметры

| Параметр | Тип | По умолчанию | Что делает |
|---|---|---|---|
| ``\\|`` | — | — | Блочный литерал YAML: сохраняет переносы строк. Так пишут многострочные скрипты |
| ``>`` | — | — | Блок со склейкой строк в одну. Для скриптов не годится |
| ``shell`` | str | `bash` | `pwsh`, `python`, `sh`, `cmd` |
| ``working-directory`` | str | корень | Рабочий каталог шага |

## Минимальный пример

```python
run: |
  # -e: выход при первой ошибке; -u: ошибка при необъявленной переменной;
  # -o pipefail: код возврата конвейера = код первой упавшей команды.
  set -euo pipefail
  NAME="$BRANCH_NAME_INPUT"
  git check-ref-format --branch "$NAME" >/dev/null
```

## Типичные задачи

**Скрипт на Python вместо shell**

```python
- run: |
    import os
    print(os.environ['GITHUB_SHA'])
  shell: python
```

**Выполнить команды в подкаталоге**

```python
- run: python app.py
  working-directory: l03_rest_api
```

## Частые ошибки

- **Забыть `set -euo pipefail`.** Без `-e` скрипт продолжит работу после упавшей команды и шаг завершится успешно, хотя всё сломалось. Каждый `run` — отдельный процесс, поэтому строку ставят в КАЖДЫЙ многострочный скрипт.
- **Подставлять `${{ ... }}` в текст скрипта.** Значение вставляется до запуска — это инъекция команд. Прокидывайте через `env`.
- **Ожидать, что переменные переживут шаг.** Каждый `run` — новый процесс; `export` не сохраняется.
- **Использовать `>` вместо `|`.** Блок `>` склеивает строки, и многострочный скрипт превращается в одну длинную строку.
