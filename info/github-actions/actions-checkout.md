# actions/checkout

```python
uses: actions/checkout@v5
with:
  fetch-depth: 0
```

**Что это.** Клонирует репозиторий в рабочий каталог задачи и настраивает git-аутентификацию.

**Зачем.** Машина создаётся пустой — кода на ней нет. Почти любой workflow начинается с этого шага. Действие заодно прописывает токен, поэтому последующие `git push` работают без настройки.

## Сигнатура

```python
uses: actions/checkout@v5
with:
  repository: ...
  ref: ...
  fetch-depth: 1
  token: ...
  path: ...
```

## Параметры

| Параметр | Тип | По умолчанию | Что делает |
|---|---|---|---|
| ``fetch-depth`` | int | `1` | **Ключевой параметр.** `1` — поверхностный клон только последнего коммита; `0` — вся история |
| ``ref`` | str | текущая | Ветка, тег или SHA, который выгрузить |
| ``repository`` | str | текущий | Другой репозиторий (для приватного нужен `token`) |
| ``token`` | str | `GITHUB_TOKEN` | Токен для доступа. Замените, если нужны права шире стандартных |
| ``path`` | str | корень | Куда клонировать — если нужны два репозитория рядом |
| ``persist-credentials`` | bool | `true` | Оставить токен в конфиге git, чтобы работал `git push` |

## Минимальный пример

```python
- name: Checkout own repo
  uses: actions/checkout@v5
  with:
    # fetch-depth: 0 — полная история вместо быстрого поверхностного клона.
    # Без неё git не сможет корректно работать с чужими ветками и push по SHA.
    fetch-depth: 0
```

## Типичные задачи

**Выгрузить два репозитория рядом**

```python
- uses: actions/checkout@v5
  with:
    path: own
- uses: actions/checkout@v5
  with:
    repository: cpython-projects/060326-flask
    path: upstream
```

## Частые ошибки

- **`fetch-depth: 1` по умолчанию — источник половины непонятных ошибок git в CI.** В поверхностном клоне нет истории: `git log`, `git merge-base`, сравнение веток и push чужих ссылок работают неправильно или падают. Нужна история — ставьте `0`.
- **`git push` не работает после чужого действия,** которое сбросило учётные данные. Проверьте `persist-credentials`.
- **Приватный репозиторий по `repository:`** требует токена с доступом; стандартный `GITHUB_TOKEN` действует только на текущий репозиторий.

## Где в репозитории

- `.github/workflows/main.yml:50` — `fetch-depth: 0`
- `.github/workflows/main.yml:48` *(строка-комментарий)* — `# fetch-depth: 0 — полная история вместо быстрого поверхностного клона.`
